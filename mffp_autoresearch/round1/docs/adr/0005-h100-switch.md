# ADR 0005 — Switch round-1 SLURM jobs to H100 (operator action)

**Status:** accepted 2026-07-29 (directed by Eloise via AskUserQuestion:
"H100 + re-cert")

## Decision

All r1-* jobs from s5_tuning-B1 seed 0 onward use `--gres=gpu:h100:1`
(partition `gpu` has 4 h100 + 11 h200 nodes), `--time=02:00:00` default.
Epoch budget is UNCHANGED (200 smoke) — a 30-min wall-clock cap was
considered and rejected (breaks epoch-based comparability with anchors,
thresholds, and the eval cache).

## Anchor carry-over (re-certification)

Batch-0 anchors + noise floor were measured on p100. To rule out a hardware
confound: one champion (`mf_fno_transfer_film`) seed-0 panel run at 200
epochs on H100 (`--no_cache`), fired alongside s5-B1 seed 0. If every
per-dataset nRMSE lands within the certified min_claimable_effect of the
batch-0 seed-0 values, anchors carry over unchanged; if not, anchors are
re-certified on H100 before any cross-hardware claim (noted provisional
until this check completes).

## Mechanics

- project.yaml sbatch.gres → gpu:h100:1; existing built scripts (s5-B1) are
  NOT edited — the orchestrator overrides at submit time
  (`sbatch --gres=gpu:h100:1 --time=02:00:00 ...` beats script headers).
  Builders dispatched after this ADR write h100 headers directly.
- p100 remains the documented fallback if h100/h200 queue pressure is bad.

## Carry-over verdict (2026-07-29): PASS

True H100 retrain (job 65989241, h100_champion_seed0_retrain.json) vs p100
seed-0: geomean 7.1171 vs 7.1034 (delta 0.0137 vs floor 0.884); per-dataset
deltas 0.0000-0.8064, every one far inside its certified min_claimable_effect
(largest, helmholtz 0.806, is 12x under its 9.695 floor). Anchors carry over
unchanged; hardware confound closed permanently. The H100-trained cap-12
champion also stands as s5-B1's same-hardware control.
