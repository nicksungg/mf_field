Glossary — the two bits of multi-fidelity jargon

Continuous fidelity index m

Multi-fidelity data is usually a ladder of fidelities, not just LF vs HF — here four grid levels 8→16→32→64, labelled m ∈ {0.0, 0.143, 0.429, 1.0}. m and resolution are correlated — m rises monotonically with grid size — but m is a separate label the dataset assigns, not one computed from the pixel count (which is why the values aren't a clean function of 8/16/32/64). It gets its own coordinate because "fidelity" in general can come from solver tolerance, timestep, or physics approximations, not only resolution; and the model uses both — each per-fidelity FNO runs at the native grid, while m is the scalar the conditioning head uses to interpolate between fidelities. Continuous means m is treated as a real number (not a discrete category), so a model can interpolate between training levels or extrapolate beyond them — the IFC idea: model the field f(x, m) as a smooth function of m, where m → ∞ is the "infinite-fidelity" (true) limit. In these diagrams the coregionalization & stack families feed m in (via B(m) = MLP[m, m²] or FiLM); the transfer & FIRE families do not — there MF lives in the training schedule, which is exactly why m is absent from those diagrams.

Per-pixel LF distribution fields mu, sigma, q10, q50, q90

FIRE makes the LF model output a distribution at each pixel (via an ensemble / MC-dropout / quantile head) instead of a single number, then summarises that distribution with five fields per pixel: mu = mean (the LF point prediction, also the base in HF = mu + delta); sigma = standard deviation = how uncertain the LF model is there (large where ensemble members disagree — sharp gradients, fronts, boundaries); q10 / q50 / q90 = the 10th / 50th (median) / 90th percentiles, which capture spread (q90 − q10) and skew without assuming a Gaussian. The LF→HF error is largest exactly where the LF model is uncertain, so feeding these channels lets the HF correction "see where LF is shaky" and concentrate its correction there.
