## Data format

Each `.npz` holds two keys:

    data    (80, 4, 24, 120)  float32   # coarse
    data    (80, 4, 64, 320)  float32   # fine
    times   (80,)             float64

Axes are `[time, (u_x, u_y, u_z, p), Ny, Nx]`.
Backward-step spans Reynolds numbers 7500 – 47500.

**The coarse and fine fields are independent OpenFOAM solves at different grid resolutions, not a downsample of one another.**
Verified: a coarse/fine pair shares an identical `times` vector (40.0 → 79.5), so the fidelities are genuinely aligned in time.
This satisfies the project's non-negotiable LF rule (see `mf_field_eloise_data/SURF_2026-main/CLAUDE.md`).

## The two training archives

`backward_step_training.tar.gz` existed on HF twice, at different sizes. Both are kept here:

|  | entries |
|---|---|
| `backward_step_training.tar.gz` (1745.1 MB) | 64 Coarse + 64 Fine + `readme.txt` |
| `backward_step_training.SUBSET48.tar.gz` (1355.3 MB) | 64 Coarse + **48** Fine, no `readme.txt` |

The smaller is a strict subset — it contains nothing the larger lacks.

**Default to the full 1745.1 MB archive.**
But do not assume the subset is corrupt: `args.json` inside `bstepWorkspace400.zip` specifies `"ntrain": 48`, exactly matching its 48 Fine files.
It may be the precise training subset used for the published results, which would make it the *methodologically correct* set for reproducing the paper's numbers.
That is unresolved, which is why both are retained.

## Status in this project

Not part of the benchmark.
A repo-wide grep for `backward_step|backwardStep|cylinder_array|cylinderArray|bstep` across every `.py`, `.json`, `.csv`, `.md` under `mf_field/` returns **zero** hits — absent from `bench_datasets.txt` (the 42-dataset roster), from `datasets_summary.csv`, from `baselines/paper_baselines.json`, and from all 2161 result JSONs.

To use them, they need converting to the `npz_l` layout `mf_field/factory_mffp/data_adapters/loaders.py` expects (`train_l<i>.npz` / `test_l<i>.npz`, keys `x`, `y`).
That is a real conversion — these are 4-channel time series, not `(N, cond)` / `(N, cells)` pairs — but a well-specified one given the `readme.txt` in each tarball.

They are an unusually good fit for `factory.md`'s stated bar of **beating published paper numbers**: the published baseline, the exact data it used, and the pretrained weights are all present together.
